请在现有项目中实现 Exchange 2019 员工邮箱自动化模块，技术栈固定为 Go + Ansible。

环境：
- Exchange Server 2019
- Exchange 主机：192.168.6.77
- ECP：https://192.168.6.77/ecp/ （仅管理页面，不要通过 ECP Web 接口自动化）
- 自动化应由 Linux 上的 Go 服务调用 Ansible，通过 WinRM 连接 Exchange Windows Server，在目标机执行 Exchange Management Shell / PowerShell。
- 服务账号：svc_exchange_auto@exchlab.local
- 密码必须从配置/环境变量/Secret 获取，禁止硬编码和打印日志。
- 邮箱主域：@bjwgby.com
- 只处理 Exchange 静态通讯组，不处理动态通讯组和普通 AD Security Group。

当前 RBAC 为最小权限，只允许：
1. New-Mailbox
2. Get-Mailbox / Get-Recipient / Get-User
3. Get-DistributionGroup / Get-DistributionGroupMember
4. Add-DistributionGroupMember
5. Remove-DistributionGroupMember

明确禁止：
- 删除 AD 用户
- Remove-Mailbox / Disable-Mailbox
- 删除通讯组
- 创建通讯组
- Update-DistributionGroupMember 整体替换成员
- 修改 Exchange Server 配置

实现两个 HTTP API：

1. 员工入职 / 创建邮箱

Exchange 创建规范，下面是一个例子：
- login_name / Alias / SamAccountName 使用 slpeng
- DisplayName 使用 江流
- 用户登录名使用 slpeng@bjwgby.com
- 最终主邮箱必须是 slpeng@bjwgby.com
- 创建使用 New-Mailbox
- 创建前使用 Get-Recipient / Get-Mailbox 做幂等检查，账号或邮箱已存在时不能重复创建
- 创建成功后按 groups 参数逐个 Add-DistributionGroupMember

2. 员工离职 / 清理通讯组
POST /api/exchange/users/{login_name}/offboard

行为：
- 根据 login_name 找到该 Exchange 用户
- 找出所有包含该用户的静态 Distribution Group
- 将用户逐个从这些组中 Remove-DistributionGroupMember
- 必须保留 AD User
- 必须保留 Mailbox
- 必须保留邮箱地址
- 不执行任何账号/邮箱删除或禁用操作
- 接口需要幂等：用户已经不在任何组时也返回成功
- 返回 removed_groups 列表，便于审计

代码要求：
- Go 负责 HTTP API、参数校验、业务编排、错误处理、日志和调用 Ansible
- Ansible 只负责 WinRM + PowerShell 执行
- PowerShell 脚本放独立文件/模板，不要把大段 PowerShell 硬编码在 Go 中
- Ansible inventory、Exchange IP、账号、端口、认证方式全部配置化
- 先实现最小可运行版本，不引入消息队列、数据库等不必要组件
- 所有操作必须幂等
- 为关键逻辑增加单元测试
