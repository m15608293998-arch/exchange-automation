## 已实现的修复

- 进入 Ansible 模板前保护外部字符串，覆盖显示名、密码和组列表，防止模板注入或密码被求值改写。
- 先校验全部请求组并按 GUID 去重，再创建 AD 用户和邮箱。
- 离职严格核对账号、UPN、邮箱类型，后续操作固定用户/组 GUID；排除启用邮件的安全组及动态组。
- 区分明确的对象不存在与权限/目录查询失败；严格校验进程退出状态和结构化结果。
- 新账号要求初始密码；匹配的已有邮箱可无密码重试，明确返回 password_applied=false。
- 增加服务 Bearer token、请求 ID 和审计结果；限制并发并对同用户操作互斥。
- 完善本地进程组超时清理、服务退出等待；用持久化 pending 记录阻止未知结果操作被盲目重试。
- 分离测试/生产配置、固定直接依赖、补充 systemd 示例及内网离线交付说明。

## 真实业务联调（2026-09-17）

目标：测试 Exchange 192.168.6.77，PowerShell 5.1.17763.316。通过 WinRM/PSRP 和内层 Exchange PowerShell 会话执行，未修改服务器权限。

| 检查 | 实际结果 |
|---|---|
| 未提供服务令牌 | 401，拒绝执行 |
| 请求不存在的组 | 422，创建前拒绝，无已确认邮箱结果 |
| 创建新账号和邮箱，并加入 app/dev | 201，created=true，password_applied=true，加入两个组 |
| 同组 GUID 与 SMTP 重复输入 | 解析后去重，没有重复添加 |
| 显示名包含 `{{ 7 * 7 }}` | 字面内容原样保存 |
| 不传初始密码重复调用 | 200，同一邮箱 GUID，created=false，password_applied=false，两组已存在 |
| 已有邮箱显示名不匹配 | 409 RECIPIENT_CONFLICT |
| 离职通讯组清理 | 200，移出 app/dev，邮箱 GUID 不变 |
| 重复离职 | 200，removed_groups=[]，仍能定位原邮箱 |
| 不存在的离职账号 | 404 USER_NOT_FOUND |

测试邮箱：`cv260917102558@bjwgby.com`；AD 对象 GUID：`14b83852-3f81-4667-9017-e0a4d3564f88`。
测试结束时该用户及邮箱保留，已从 app/dev 移出。没有执行账号/邮箱删除或禁用。

联调发现：当前 RBAC 的 Get-Recipient 不开放 DomainController 参数。代码现对该只读冲突查询检查参数能力；邮箱创建、回读及组操作继续使用配置的 DC。此问题不是 WinRM 登录失败。

性能样本：创建并加入两个组约 106 秒；无密码重复确认约 105 秒；移出两个组约 79 秒；空组离职约 26 秒。联调业务超时配置为 10 分钟。生产需要按真实组数量评估超时及容量，不能从这个小规模样本推断批量吞吐。
