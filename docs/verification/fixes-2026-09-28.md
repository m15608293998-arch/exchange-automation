# 0.2.1 修复验收（2026-09-28）

范围：外网测试 Exchange `192.168.6.77`，Windows Server 2019、Windows PowerShell 5.1、Python 3.13.15。未连接内网生产环境，未重启服务器、修改全局关机策略、防火墙或 RBAC。

## 修复与回归

- 旧状态文件识别核对记录中的账号，避免 `alice` 的 `account-alice.pending` 误锁 `account-alice`；旧空文件和损坏文件仍阻止不安全重试。
- PowerShell 桥接隔离 Warning/Verbose/Debug/Information 输出，只返回业务 JSON；Windows 原生测试验证警告不污染成功结果、原始诊断内容不泄漏、真正错误仍返回失败。
- 停服等待业务线程结束后，最多再等待 5 秒发送响应。修复前慢客户端收到 2,880 / 104,094 字节，修复后收到完整 104,094 字节；不读取的客户端不会无限阻塞停服。
- 接收 Windows `PRESHUTDOWN`；注册时设置本服务专用等待预算，覆盖最大业务超时及排空时间。实机读回 `1835000` 毫秒、接受预关机通知；全局 `WaitToKillServiceTimeout` 保持原值 `600000`。
- 组成员校验改为按固定组 GUID 和成员 DN 的服务器端过滤，不再枚举全组成员；原受限账号对 6 个测试组的查询与独立成员读取结果一致，包含存在和不存在成员两种情况。
- 建号脚本只输出交付报告，删除旧 Linux/systemd 连接文件及说明；加退组测试补充 GUID、域控、绕过开关及禁用确认提示的参数断言。

回归结果：Linux Python 20 项中 16 项通过、4 项 Windows 专用测试跳过；Windows Python 20 项全部通过。原生 PowerShell：业务 26、桥接 4、建号 128、只读采集 39 项全部通过。建号模拟的预期失败分支会输出错误提示，不代表实际建号失败；这些测试不写 AD。
