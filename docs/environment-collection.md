# 生产前只读采集：给内网管理员

只需要复制 [Get-ExchangeEnvironment.ps1](../deployment/Get-ExchangeEnvironment.ps1) 这一个文件，**此时不要执行创建账号的 Initialize 脚本**。

## 执行方法

在计划给程序连接的 Exchange 服务器上，用管理员身份打开已有的 **64 位 Exchange Management Shell**，进入脚本所在文件夹，执行：

```powershell
.\Get-ExchangeEnvironment.ps1
```

不填任何参数，不输入账号、密码或邮箱后缀。中文注释和输出使用 UTF-8 BOM 编码，直接复制文件即可，不要另存为 ANSI。脚本本身只输出屏幕/管道，不写文件。

如管理员允许将结果保存到本机，改用下面这条命令；**唯一的文件写入是管理员明确执行的 Out-File**，不会修改 Exchange/AD，也不覆盖已有同名文件：

```powershell
.\Get-ExchangeEnvironment.ps1 | Out-File .\Exchange-Environment.txt -Encoding utf8 -Width 4096 -NoClobber
```

已有同名文件时换一个报告文件名。若不允许落盘，可直接复制屏幕的完整输出。把经过管理员审核的报告回传即可；出现“查询失败”也请保留，我们据此判断差异，不要为了采集自行扩大权限或关闭安全策略。

普通 PowerShell 中缺少 Exchange 命令时，脚本会明确停止，请改用 Exchange Management Shell。若组织执行策略阻止脚本，应交管理员按既有审批/签名流程处理；不要求修改执行策略或使用 Bypass。

## 查什么、明确不做什么

脚本按 13 个小节排列，每节都有中文用途和操作说明，仅查询：

- Windows、PowerShell、.NET、Exchange 版本及现有执行策略。
- AD 域、可写域控、允许的 UPN 后缀，以及本机 IP/DNS。
- 邮箱数据库名称和状态、接受域、邮件地址策略模板。
- PowerShell 虚拟目录认证/HTTPS/扩展保护、IIS 证书公开信息和依赖服务状态。
- 当前 Shell 的相关命令可见性、四类内置业务角色及命令参数、现有自定义/独占管理范围。

不会创建用户/邮箱、分配权限、更改角色/组/成员、修改服务或网络、安装模块、访问公网、导出私钥，也不查询员工名单、邮件内容和密码。`New-*`、`Set-*`、`Remove-*` 等名称只作为 `Get-Command` 或角色元数据查询的字符串，**不会执行这些写命令**。

报告仍含内网域名、地址、证书名称和角色/范围定义，属于内部信息，应按组织要求审核并走批准渠道回传。无需提供管理员密码。
